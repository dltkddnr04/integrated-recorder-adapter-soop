This revision updates `tests/streamlink-grid-poc/` without changing the Go Grid PoC,
the production Source Adapter, Integrated Recorder Core, or Streamlink itself. It is
still classified as **Experimental/Beta**, not stable long-recording software.

## Implemented and verified

- Public bootstrap no longer requires a live-list page. It checks the exact requested
  channel/BNO against Live metadata and requires a normal positive Watch response.
  Explicit restrictions and unknown/malformed required fields fail closed. It does
  not search for or switch to another broadcast.
- Video TS PES packets carry both PTS and DTS. DTS comes from the observed Grid
  decode-order timestamp. POC types 0/1/2 are parsed; fixed VUI timing maps reordered
  pictures to PTS. When observed POC remains ordered, Grid time supplies both PTS
  and DTS; reordered pictures without fixed VUI timing fail closed. PCR follows DTS.
  Internal timestamps remain unwrapped; 33-bit wire fields wrap as specified. This
  remains a supported subset, not a universal H.264 parser.
- Synthetic B-frame H.264/AAC TS passes FFmpeg 9 full decode with `-xerror`, monotonic
  DTS, PTS reordering, PTS≥DTS, and closely aligned synthetic stream start times.
  A preserved historical private Grid capture also passed the new complete decode
  with no DTS warning. No new live capture was made using this revision; subjective
  A/V sync is not claimed.
- Single-active-Parent candidate failover, one fresh Center rediscovery per outage,
  cancellation, limits and exact cached-overlap validation pass synthetic and local
  loopback tests. It refuses to paper over an absent overlap or a gap. A 128-entry
  identity history bounds dedup memory.
- Default recording continues until the upstream stream ends or the user stops it.
  Optional `--soop-grid-duration` and `--soop-grid-max-bytes` limits are available.
  Queue/frame/index storage is bounded independently of recording length. The
  8192-packet guard now measures a no-media/control window and resets on accepted
  media; packet statistics remain cumulative.
- The external `soop_grid` plugin delegates `hls` to Streamlink's installed built-in SOOP
  plugin. `auto` tries Grid first and may use HLS only for an allowlisted initial
  transport failure before Grid output. Authentication denial, protocol/media
  errors, and midstream failures do not silently switch or combine timelines.
- `dist/soop_grid.py` is generated by the existing static AST bundler. The installed name
  is `soop_grid.py`, preserving the built-in `soop` plugin. A clean Streamlink 8.6.2
  environment with only Streamlink and its own dependencies, no project package,
  and no `PYTHONPATH` passes sideload discovery and offline stream enumeration.

## Deliberately not implemented / not proven

Concurrent active-active Parent sessions and a multi-parent aggregator are not
implemented. SOOP's concurrency allowance, shared node-key scope, cross-parent frame
number identity and byte identity are not established. The receiver continues to
use one Parent at a time.

Live server support for cache overlap, natural Parent failure/recovery, or Center
rediscovery after an outage is not verified. Local tests cannot establish that a
live Parent retains the needed overlap. Recovery terminates with an explicit error
when continuity cannot be proven.

The optional duration clock begins at Parent reception, after bootstrap, and covers
Parent control/recovery work. Automatic reauthentication/certificate refresh,
broadcast end-vs-network-failure classification, automatic BNO rollover, crash
resume, and long-duration drift/wrap have not been implemented or established.
Filesystem durability on power loss and multi-hour operation are also untested.

The HLS path is tested through a mocked built-in plugin; no fresh live HLS request
was made. Grid live capture, live failover, 30-minute/3-hour/6-hour endurance,
multi-parent live reception, and macOS/Windows execution were not tested in this
revision. Linux Streamlink 8.6.2/Python 3.12.3 clean-venv discovery was tested.

## Field validation follow-up — 2026-10-25 UTC

The generated `dist/soop_grid.py` was loaded under the sideload filename used by that
historical revision, with Streamlink 8.6.2 in a clean Python 3.12 environment and no
project package or `PYTHONPATH`. Normal
public Watch, Gateway, Center, and Parent setup succeeded. Two capped Grid runs ended
before their requested 300-second limit: one at 174.238 seconds and a second at
256.094 seconds. The second process exited 1 with an empty captured diagnostic stream;
the reason is unknown. Neither is a completed five-minute endurance run.

The first run's private receiver sidecar recorded 10,780 `0xC748` packets
(155,812,865 media payload bytes) and 160,557,452 bytes of MPEG-TS. The second TS was
236,163,908 bytes. FFprobe identified both as H.264 1920×1080 at 60 fps with AAC
48 kHz stereo. The second run contained 15,360 video packets and had 256.094 seconds
of container duration.

FFmpeg 9 decoded both complete captured audio/video TS files with `-xerror`, exit 0,
and no diagnostics. For the first run, FFprobe read 10,440 video packets with zero
non-monotonic DTS events and zero PTS-before-DTS packets; 7,743 recorded Grid video
chunks had B-slices. For the second run, FFprobe read 15,360 video packets with zero
non-monotonic DTS events and zero PTS-before-DTS packets; PTS reordered in decode
packet order as expected for B-frame content. A TS scan found 188-byte sync, PAT/PMT,
monotonic PCR (15,360 samples), and no payload continuity-counter errors. The first
run's receiver sidecar recorded zero frame sequence gaps. The second run's audio
started 94 ms before video and its measured stream durations differed by about 491 ms;
these timestamps are observations, not a perceptual A/V sync verdict. The short-run
process RSS stayed around 40–41 MiB, but this is not multi-hour memory validation.
Wire/Payload/media captures remain private in temporary storage and are not in Git.

A single normal Center discovery returned one usable Parent endpoint. Because the
server did not provide a second distinct same-quality candidate, no second connection
was attempted. Multi-Parent active-active remains unverified and unimplemented.

A separate short live run through `--soop-grid-transport hls` delegated to the
Streamlink built-in SOOP plugin and received 3,887,840 bytes of HLS TS; FFprobe saw
H.264 960×540 at 60 fps and AAC 48 kHz stereo. The sample was interrupted during a
segment: full `-xerror` decode failed on a corrupt/truncated packet. This verifies
live HLS delegation and byte reception only, not a complete HLS recording. The built-in
plugin remained loaded alongside the external sideload plugin.

The offline test PCR scanner was corrected to recognize PCR only when the adaptation
field is large enough to contain the PCR flag. This fixes a false positive in the
test parser; it does not change the TS muxer.

Current field status: short live Grid capture, B-slice decoding, and TS timeline
checks are verified; a complete five-minute capture, 30-minute/3-hour/6-hour
endurance, live Parent failover, live
multi-parent reception, clean HLS segment-boundary completion, automatic session
reauthentication, and broadcast-end classification remain unverified. Only Linux
was run directly; Windows/macOS are covered by a newly added CI matrix but have not
yet had a hosted workflow result.
